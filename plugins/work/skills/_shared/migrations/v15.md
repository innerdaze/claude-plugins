# v15 — an artifact row never points at a file that does not exist

**What changed:** the `Ticket flow` row in `## Artifacts` is `none` when the project has no
workflow overlay, and the `Ticket flow rules` row is absent when there are no extracted rules —
which is what `init` writes and what the template says. v4 broke that for migrated projects: its
step 5 rewrote the `Ticket flow` row to `.agent/work/workflow.md` unconditionally, including rows
that read `none` because no overlay had ever been created. Every doctor in the stack runs the
shared artifact check, so every one of them then reported *"artifact 'Ticket flow' owned by
delivery points at '.agent/work/workflow.md', which does not exist"* — a finding about a file
nobody ever had, in a project doing nothing wrong.

**Preconditions:** the bus lives at `.agent/PROJECT.md` (v4). Decline with "waiting on v4"
otherwise.

**Apply (v14 → v15):**

1. **`Ticket flow`.** Read the row. If its path is `none`, or names a file that exists → leave it.
   If it names a file that **does not exist** → set the path to `none`. The overlay is optional
   and `none` is the state every reader already handles; a row naming a missing file is not a
   registered artifact, it is a dangling reference. Say in the report which it was.

2. **`Ticket flow rules`.** If the row names a directory that does not exist, or exists and is
   empty → **remove the row**. v11's own rule: an absent row means "no extracted rules", and the
   directory is not created to justify a row.

3. **Touch no other row.** Other owners' artifacts are theirs to resolve; the shared check will
   keep reporting them under their owner's name, which is the correct outcome.

4. **Report** what you changed, and — if you set `Ticket flow` to `none` — that
   `/work:update-workflow` registers the overlay again the day one is written.

`[note]` The rule broken here is the one the shared check enforces: a row in `## Artifacts` is a
claim that the artifact exists, and a plugin's migration may not make a claim on the project's
behalf. Repointing a path is fine; conjuring one is not.
