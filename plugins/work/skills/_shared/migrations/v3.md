# v3 — the config bus gains its three shared sections

**What changed:** The bus grew `## Artifacts` (who owns which artifact, and where), `## Versions`
(one row per component with its owning role) and `## Commands` (the command that migrates each
role). The single `Domain system version` table row is replaced by per-component `## Versions`
rows, because each owner now sets its own floor and there is no one number a project is behind on.

**Preconditions:** none. This applies wherever the bus currently lives, including the legacy
`domains/PROJECT.md` path — moving the file is a separate migration, and this one must not wait
for it.

**Apply (v2 → v3):**

1. **Locate the bus.** `.agent/PROJECT.md` if it exists, else `domains/PROJECT.md`. Apply
   everything below to that file, in place. Do **not** move it.

2. **Add `## Artifacts` if absent** (skip the whole step if the heading is already there), with
   the marker `<!-- owner: shared, additive -->` and only the rows `work` owns.

   **Copy the three heading lines verbatim**, with the spacing shown — they are what `init`
   writes, and a run that re-computes the alignment produces a different diff from one that
   copies it:

   ```markdown
   ## Artifacts            <!-- owner: shared, additive -->
   ## Versions             <!-- owner: shared, additive -->
   ## Commands             <!-- owner: shared, additive -->
   ```


   | Artifact | Path | Owner |
   |---|---|---|
   | Ticket flow | `domains/workflow.md`, or `none` if no overlay exists | delivery |

   Add a `Knowledge` row **after** the `Ticket flow` row — appended, not inserted, because two
   runs that place it differently produce two diffs of the same migration — pointing at
   `domains/` with owner `knowledge` **only if `domains/` exists** — `work` still owns that system today, so registering it here is registering its own
   artifact. If a separate knowledge tool already registered it, leave that row exactly as it is.

3. **Add `## Versions` if absent**, marker `<!-- owner: shared, additive -->`. Seed it from what
   the project already has, not from the skill's canonical numbers:

   | Component | Version | Owner |
   |---|---|---|
   | manifest schema | 1 | shared |
   | ticket-flow overlay | the overlay's own stamp, or omit the row when no overlay exists | delivery |
   | delivery scaffolding | the value from the old `Domain system version` row (missing ⇒ 1) | delivery |

   **Write no `knowledge scaffolding` row**, even though `work` scaffolds that system today. The
   old `Domain system version` is a number in *`work`'s* scheme, and the knowledge system's
   owner keeps its own — so copying the value across would not be recording a stamp, it would be
   inventing one. It also reads as **higher** than the knowledge plugin's own canonical version,
   and a stamp at or above canonical means "up to date": the first real knowledge migration would
   be skipped in every project that came through here, silently, which is the one failure a
   version stamp exists to prevent.

   An absent row is the honest state and a complete finding — "knowledge is not registered" —
   and the row appears with a truthful number the first time its owner runs. This is the same
   rule as step 4's *declare no other role's row*, applied to versions instead of commands.

   ⚠️ **Carry the project's existing numbers across. Do not stamp canonical here** — that is step
   7 of `migrate.md`, after every pending migration has actually run. Stamping current at the
   start of a chain would skip the rest of it silently.

4. **Add `## Commands` if absent**, marker `<!-- owner: shared, additive -->`, and copy this
   note **verbatim** — both sentences. It is what stops a later reader inferring a frozen row
   shape from the two frozen tables above it, so a summary of it does not do its job, and two
   developers summarising differently is two diffs:

   ```markdown
   > **This table's row shape is _not_ part of the frozen core, unlike `## Artifacts` and
   > `## Versions` above.** It may gain columns. Do not infer otherwise from its neighbours.
   ```

   Then the table, with this row and no other:

   | Role | Migrate | Re-scaffold |
   |---|---|---|
   | delivery | `work migrate` | `work init` |

   Declare **no other role's row.** An absent row is the correct answer for a tool that is not
   installed, and it is what makes "stale, and its command is not available here" a complete
   finding rather than a guess.

5. **Remove the old `Domain system version` row** from the config table. This is a deliberate
   deletion, and it is legible: the value moved to `## Versions` in step 3, in the same diff, and
   nothing else in this migration reformats or reorders anything.

6. **Leave every other section untouched** — including sections owned by roles that are not
   installed here. This migration adds three sections and removes one row; anything else it
   touched would be outside what it declared.
