# v12 — `.agent/local/` is the one place uncommitted things live

**What changed:** Everything a tool or a project writes that must **not** be committed now lives
under **`.agent/local/`**, ignored as a single directory. That replaces the per-file convention
(`SESSION.local.md` and friends), each of which needed its own ignore entry.

Three reasons, and the second is the one that bit:

- **One ignore entry instead of one per file.** Every new local file was a chance to forget one.
- **A stale entry commits the file.** `cadence`'s own first migration exists partly to repair an
  ignore entry that had stopped matching after a path moved — and an ignore entry that matches
  nothing is indistinguishable from one that works, right up until the file appears in a diff.
- **It is one place per developer.** A preference belongs to the person, not the checkout, so the
  directory is meant to be *shared* across worktrees — by a symlink the user creates. Anything
  that must differ per checkout is keyed by worktree in its own filename instead.

**Preconditions:** the bus lives at `.agent/PROJECT.md` (v4). Decline with "waiting on v4"
otherwise.

**Apply (v11 → v12):**

1. **Ignore the directory.** Append `.agent/local/` to the project's ignore file if it is not
   already there, through the VCS's own mechanism (git: `.gitignore`). Idempotent — if a line
   already matches that path, change nothing.

   **Do not create the directory, and do not touch it if it exists.** `work` puts nothing in it
   today, so creating one achieves nothing — and if it is already there as a **symlink**, that is
   a user sharing one local directory across their worktrees, which is what it is for. Replacing
   a link with a directory would silently un-share their settings.

2. **Do not move another role's local files.** If `.agent/cadence/SESSION.local.md` or any other
   role's local state exists, **leave it exactly where it is** and say so in the report: its owner
   moves it, on its own schedule, with its own migration. Moving it here would be `work` editing
   another role's artifact, and the fact that the destination is a shared directory does not make
   it `work`'s to write.

3. **Leave stale ignore entries for other roles' files alone**, for the same reason — with one
   exception: an entry naming a path **`work`** used to write. There are none today, so in
   practice this step does nothing; it is stated so the next person does not have to decide.

4. **Report** the ignore entry you added, and every local file you found belonging to a role that
   has not moved yet, naming that role's migrate command.

`[note]` The overlay's step schema gained a `Settings` field in the same release, and settings
values are read from this directory. That is the overlay's own version (schema 4) and upgrades
through `work update-workflow refresh`, not here — an overlay with no declared settings stays
valid, so nothing is stranded.
