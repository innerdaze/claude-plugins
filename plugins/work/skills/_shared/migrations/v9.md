# v9 — the frozen-core markers the pre-v3 template never wrote

**What changed:** v3 introduced owner markers and wrote them on the three sections it created.
The sections the *older* template generated — `## Tracker operations` and `## Notes` — kept bare
headings, and a bare heading is **drifted** by the shared bus checks: unowned, so nothing
maintains it. A project that migrated v2 → v8 therefore passed every version check and then
failed its own doctor on files the migration had just written. This closes that gap.

**Preconditions:** the bus lives at `.agent/PROJECT.md` (v4). Decline with "waiting on v4"
otherwise.

**Apply (v8 → v9):**

1. **Mark the two sections the pre-v3 bus template generated**, where they are present and bare.
   The marker goes on the heading line, separated by **exactly one space** — not padded to line
   up with the sections above, which is whitespace no check reads and two runs pad differently:

   - `## Tracker operations` → `<!-- owner: shared -->`, which is what `templates.md` writes for
     a freshly scaffolded project. It documents how to reach *this* project's tracker, and
     `cadence` needs those calls as much as `work` does — the same reasoning that makes
     `## Tracker` itself belong to no role.
   - `## Notes` → `<!-- owner: shared -->`. Anyone may append a working agreement there and
     nothing rewrites it wholesale. Marking it `delivery` would license `work` to edit the user's
     own prose, which its boundaries forbid.

   Both markers must match what `init` writes, or the same section ends up owned differently
   depending on whether a project was scaffolded or migrated — and a doctor cannot tell which of
   the two is the mistake.

   If a section already carries a marker — **any** marker, including one you would not have
   chosen — leave it exactly as it is. The project has answered, and re-answering is how two
   developers produce two diffs.

2. **Report every other bare heading; do not mark it.** List each one and say it is unowned, that
   its owner's tool has to claim it or the section should be deleted, and that `work doctor` will
   keep reporting it until then.

   `work` must not guess here, and the reason is structural rather than cautious: **the only
   section names it can recognise are its own.** Role ids are not plugin names and sibling
   sections are not `work`'s to enumerate — a table mapping `## Execution` to `methodology` would
   be `work` learning another plugin's business, which is exactly what the bus exists to avoid.
   Writing `shared` over a section that in fact belongs to a role is worse than leaving it bare:
   a bare heading is a defect every doctor already reports, whereas a wrong owner reads as
   settled and silences the report that would have found it.

3. **Change no marker that already exists, and no section body.** This migration adds markers to
   heading lines and nothing else — one kind of change, so its diff can be read rather than
   skimmed.

4. **Add the schema marker if it is absent.** Directly under the bus's H1, its own line,
   followed by a blank line:

   ```markdown
   <!-- manifest schema: 1 -->
   ```

   The pre-v3 template never emitted it, so a project can carry a `| manifest schema | 1 |` row
   in `## Versions` and still have no marker — which is what the shared bus checks actually read,
   and they call its absence drifted. The row is a component's stamp; the marker is the file's
   format, and one does not stand in for the other. If a marker is already present, leave its
   value alone even if it is higher than 1: the value is not frozen and is not yours to lower.

5. **Report** which headings you marked, which you left bare and why, whether you added the
   schema marker, and that the bus should now be clean under `work doctor`.
