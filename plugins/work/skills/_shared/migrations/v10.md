# v10 — the settings table becomes the six `shared` sections

**What changed:** The bus's loose key/value table is gone. Its keys now live in
**`## Project`**, **`## Environment`**, **`## Version control`**, **`## Tracker`**,
**`## Verification`** and **`## Bindings`** — every one marked `shared`, because every tool needs
these values and **any** tool can legitimately be the one that asked the user, since any of them
can be installed first.

That table was the last region of the bus with no ownership mechanism at all, and the most
contested one: every installed tool reads it and more than one writes it. Its rule — write a row
that is absent, never overwrite a value another wrote — lived in prose in this plugin's own
template, where no doctor could check it and no adopter could see it.

**Preconditions:** the bus lives at `.agent/PROJECT.md` (v4). Decline with "waiting on v4"
otherwise.

**Apply (v9 → v10):**

1. **Create the six sections**, in this order, directly below the bus's opening prose and above
   `## Artifacts`. Copy these heading lines verbatim, spacing included:

   ```markdown
   ## Project              <!-- owner: shared -->
   ## Environment          <!-- owner: shared -->
   ## Version control      <!-- owner: shared -->
   ## Tracker              <!-- owner: shared -->
   ## Verification         <!-- owner: shared -->
   ## Bindings             <!-- owner: shared, additive -->
   ```

   Each takes a `| Key | Value |` table, except `## Bindings`, whose columns are `| Seam | Kind |`.

2. **Move each key to its section, renaming only where the section already says the noun.** The
   value is carried across **byte-for-byte** — this migration moves values, it never re-detects,
   reformats or improves one:

   | Old row | New home | New key |
   |---|---|---|
   | `Project name` | `## Project` | `Name` |
   | `Environment` | `## Environment` | `Stack` |
   | `Version control` | `## Version control` | `Kind` |
   | `Commit workflow` | `## Version control` | `Commit workflow` |
   | `Ticket tracker` | `## Tracker` | `Kind` |
   | `Tracker access` | `## Tracker` | `Access` |
   | `Ticket prefix` | `## Tracker` | `Prefix` |
   | `Verification` | `## Verification` | `Proven by` |
   | `Doc system` | `## Bindings` | `Doc system` |
   | `Intent` | `## Bindings` | `Intent` |
   | `Shared knowledge` | `## Bindings` | `Shared knowledge` |

   A row the old table did not have is simply absent from its new section — do not invent a
   placeholder, and do not go detecting a value to fill it. Absent is a state every reader
   already handles.

3. **Drop the `Workflow overlay` row — but only after checking `## Artifacts` records the path.**
   The overlay is registered as the `Ticket flow` row there, so the old row was the same fact in
   a second place, and two places that can disagree is what the registry exists to remove.

   **Before deleting**, compare. If `## Artifacts` has no `Ticket flow` row, or its path is
   `none` while the config row names a real file, **write the path into `## Artifacts` first**,
   then delete.

   If the two disagree on a real path, **stop — and hand the user the choice**, because a
   contradiction is theirs to resolve and a dead end is not a resolution. Report both paths and
   say which file each came from; say for each whether it exists on disk and, when both do,
   which was modified more recently. Then offer: **register the `## Artifacts` path** and drop
   the config row, **register the config row's path** instead, or **stop here** to reconcile by
   hand. Apply the choice, and record it in the report — the reviewer should see a decision, not
   an unexplained edit.

4. **Keys this table does not recognise stay, and stay visible.** Put them in a
   `## Configuration        <!-- owner: shared, additive -->` section — created *only* if such
   keys exist — and **name every one of them in your report**, so the reviewer can move it into
   the right section in this same merge request. A project that added a key by hand is telling
   you something the template does not know; dropping it silently is the one unacceptable outcome.

5. **Leave `## Artifacts`, `## Versions`, `## Commands` and every other section alone**, apart
   from the single `## Artifacts` path repair step 3 may require.

6. **Report** the sections you created, each key's old and new home, whether you dropped the
   overlay row and what `## Artifacts` said when you did, and any unrecognised key you parked.

`[note]` This is the change that retires the tracker handover in practice. `cadence` was once to
*take over* `## Tracker` on install, rewriting its owner marker; the handover conflated **which
tracker this project uses**, an environment fact, with **what to work on next**, which is
`cadence`'s and already lives in `## Execution`. Claiming the section claimed the fact rather
than the decision.
