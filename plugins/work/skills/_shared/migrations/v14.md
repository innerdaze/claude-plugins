# v14 — retired command names are repointed where `work` owns the file, and reported where it does not

**What changed:** at 0.2.0 this plugin's skills lost their redundant prefix: `/work-on` became
`/work:on`, `/work-init` → `/work:init`, `/work-scan` → `/work:scan`, `/work-migrate` →
`/work:migrate`, `/work-update-workflow` → `/work:update-workflow`. The plugin namespace supplies
the prefix now. Nothing at the time told a project that had *stored* one of the old names — in
its workflow overlay, an extracted rule, or another tool's binding — and a real upgrade found
`/work-on` still named as the delivery command months later.

**Preconditions:** the bus lives at `.agent/PROJECT.md` (v4). Decline with "waiting on v4"
otherwise.

**Apply (v13 → v14):**

1. **Repoint inside `work`'s own artifacts.** In `.agent/work/workflow.md` and every file under
   `.agent/work/rules/`, replace each retired name with its current one, exactly as listed above
   — a whole-token match, so `/work-on` changes and prose like "work on the ticket" does not.
   Change nothing else in those files.

2. **Scan the repo for what remains.** Search the tracked files for the five retired names.
   **Edit none of them**: each is another role's artifact or the project's own prose. Report every
   occurrence with its owner and the fix:

   | Where | Whose | Fix |
   |---|---|---|
   | the bus's `## Execution` → `Skill` | the role that owns that section (its owner marker) | that role's re-scaffold command from `## Commands`, which re-detects the delivery skill and confirms it; or a one-word hand edit of the row |
   | `CLAUDE.md` outside the `## Rules` section, READMEs, docs | the project | a hand edit; say the line |
   | anything else | its owner marker, if it has one | that owner's re-scaffold command |

   A reference in an uncommitted or ignored file — a personal memory, a saved command — is
   outside every migration's reach; say so once rather than listing it.

3. **Report** what you repointed, file by file, and every occurrence you left with its fix.
   Where the bus's `## Execution` names a retired command, lead with that one: it is the reference
   that stops a session from handing off at all.

`[note]` The rule this applies is the one every repoint here has applied: a plugin fixes the
references inside the files it owns, publishes the fact, and the owner of every other file acts
on it. The fact here is the rename itself, and the only place it was published was this plugin's
skill names — which nothing else reads. This migration is the publication.
