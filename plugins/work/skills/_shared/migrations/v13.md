# v13 — the bus is a map for the plugins, not a document for people

**What changed:** The bus template no longer emits anything addressed to a reader. Gone: the
opening prose under the schema marker, the explanatory paragraphs inside sections, the
`## Tracker operations` how-to list and the `## Notes` section. What remains is the frozen core
plus rows. `work on` now takes tracker operations from its own `tracker-ops.md` by
`## Tracker → Kind`, so the bus says *which* tracker and *how it is reached*, never how it is
driven.

Why: every plugin loads the bus blind, first, on every run, and none of them reads prose. On a
real bus the preamble, the paragraphs and `## Notes` were over a third of the tokens. And
`## Notes` had become where working agreements went when `CLAUDE.md` felt full — a second
`CLAUDE.md` that every plugin pays for and no plugin uses.

**Preconditions:** the six `shared` sections exist (v10). Decline with "waiting on v10"
otherwise.

**One rule for the whole migration: delete deterministically, quote everything deleted in the
report, place nothing.** Two developers must produce the same diff, and a line that turns out to
matter is recovered from the report, not lost. Where a deleted line belongs is a judgement — a
working agreement to `CLAUDE.md`, knowledge to a `domains/` topic, a plugin's behaviour to that
plugin's own procedure — and a migration making that judgement is a quiet edit to a file nobody
chose to change.

**Apply (v12 → v13):**

1. **Delete the opening prose.** Every non-blank line between `<!-- manifest schema: 1 -->` and
   the first `## ` heading. Quote each in the report.

2. **Delete prose inside the `shared` and `shared, additive` sections.** Within each of the nine
   — `## Project`, `## Environment`, `## Version control`, `## Tracker`, `## Verification`,
   `## Bindings`, `## Artifacts`, `## Versions`, `## Commands` — a line that is not the heading,
   not blank and does not start with `|` is prose, and goes. Quote each in the report. **A
   section owned by any other role is not touched at all**, prose included; nor is a section with
   no owner marker that `work` did not emit (report it as unrecognised, as v9 does).

   A quoted line that was a project fact rather than an explanation becomes a `| Key | Value |`
   row — **by hand, after review.** Prose is not how the bus states a fact, so the migration is
   right to remove it either way.

3. **Delete `## Tracker operations`** wholesale. `work on` derives the operations from `Kind`
   now. Quote its bullets in the report; a custom call for a tracker `tracker-ops.md` does not
   list is knowledge about that tracker and may become a `domains/` topic.

4. **Delete `## Notes`** wholesale. Quote every bullet in the report under *"these were in
   `## Notes`; the bus holds none of them"*. The prefix-normalisation bullet was `work`'s own and
   needs no home (`work on` reads `Prefix` directly). Everything else is the project's to place.

5. **Delete `n/a` rows.** In the five `shared` settings sections, remove any row whose value is
   exactly `n/a` (case-insensitive, backticks or not). Absent means unknown; `none` is a value
   and stays.

6. **Report, do not edit, values that read as instruction.** If `Commit workflow` or
   `Proven by` holds more than a command — *never*, *always*, *confirm with*, a numbered procedure
   — quote it and suggest the fact form. Whether a sentence is a fact is not for a migration to
   decide.

7. **Report**: what steps 1–5 removed, verbatim, grouped by step; what step 6 flagged; and the
   one line that says where each kind of thing goes (agreement → `CLAUDE.md`, knowledge →
   `domains/`, plugin behaviour → that plugin).

A bus already in this shape — nothing between the marker and the first heading, tables only, no
`## Notes`, no `## Tracker operations`, no `n/a` — produces an empty diff and is stamped. That is
the correct outcome, not a failed run.
