# v11 — register the overlay's extracted rules as an artifact

**What changed:** `## Artifacts` gains a **`Ticket flow rules`** row naming `.agent/work/rules/`,
alongside the `Ticket flow` row that already names the overlay.

v4 moved those rules from `.claude/rules/workflow/` and repointed the references *inside* `work`'s
own files. It could not repoint the references inside `domains/**`, because that content belongs to
another role — so a migrated project is left with knowledge files pointing at a directory that no
longer exists, and the only owner allowed to fix them cannot discover where they went. Registering
the directory turns "where the rules live" into a repo fact its owner published, which is the one
way another plugin may act on it.

**Preconditions:** the bus lives at `.agent/PROJECT.md` (v4). Decline with "waiting on v4"
otherwise.

**Apply (v10 → v11):**

1. **If `.agent/work/rules/` exists and holds at least one file**, append to `## Artifacts`:

   ```markdown
   | Ticket flow rules | `.agent/work/rules/` | delivery |
   ```

   Appended after the last existing row, never inserted — row order carries no meaning, so any
   other placement is a diff two runs disagree about.

2. **If the directory does not exist, write no row.** An absent row means "no extracted rules",
   which is the correct state for most projects and a complete answer for anyone reading it. Do
   not create the directory to justify a row.

3. **If a `Ticket flow rules` row is already present**, leave it exactly as it is, including a
   path you would not have chosen. It is `delivery`'s row and the project has answered.

4. **Report** whether you added the row, and — if you did — that the knowledge system's own
   migrate command can now repoint any of its files that referenced the old
   `.claude/rules/workflow/` path.
