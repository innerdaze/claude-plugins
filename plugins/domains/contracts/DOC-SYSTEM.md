# The doc-system contract

*What a tool may ask a knowledge system, stated without reference to how any knowledge system
works. This file is the versioned contract; a binding satisfies it through an adapter.*

**Contract version: 1.** Additive changes — a new optional operation, a new optional field — are
minor. Removing an operation or changing what one means is breaking.

## Why a contract at all

So that **nothing has to read this plugin's files to use a repo's knowledge.** A tool that wants
*what applies to what I am about to touch* asks these three operations. It does not learn where
knowledge lives, what format it is in, or that this plugin exists.

## The three tiers

| Tier | What | Where |
|---|---|---|
| **Contract** | this file — operations, inputs, outputs, all tool-agnostic | shipped here |
| **Fallback** | [`markdown`](../adapters/markdown.md) — files on disk, assumes only a filesystem | shipped here |
| **Adapter** | the binding to whatever this project actually has | **project-local**, generated by `domains init` |

**Resolution order:** project-local adapter → shipped `markdown` fallback → error naming the
command that generates one. Nothing ever needs a sibling tool's source, because the adapter is
*generated against what is present* rather than derived from anyone's code.

## Operations

### `locate(topics, paths?) → ranked entries`

**Which knowledge applies here.** Two-phase by design: digests first, bodies on selection, so a
caller can decide what to pay for before paying.

| Input | Required | Meaning |
|---|---|---|
| `topics` | **yes** | topic slugs or free text the caller is working on |
| `paths` | no | the files or areas the caller is about to touch |

`paths` is the signal that still works when a ticket title is thin — which is exactly when
discovery matters most. An adapter that cannot match on paths declares it `unsupported` and
answers on topics alone; it does not silently ignore the argument.

**Output is ranked, and the rank means something.** A caller under a context budget takes the top
N. An unordered answer forces it to truncate arbitrarily, which is how the wrong entry gets
dropped.

Each entry carries: `topic`, `title`, `digest` (one line), and `body` when the caller asked for
bodies. Absent knowledge is an **empty result, never an error** — a repo with nothing recorded on
a topic is a normal repo.

### `record(note) → entry`

**Persist a durable convention or gotcha.** Mints a new topic when none fits, and lands
immediately rather than queueing for review: this is the project's own memory, written where
review already exists around it.

Why no proposal queue, since a shared-memory service has one: **queues exist because knowledge is
leaving the repo**, where a wrong entry reaches other people. This never leaves.

`record` is the one operation that makes this system **single-writer**. A caller that has this
binding writes knowledge *through it* and never edits the files directly — two writers on one
artifact is what ownership rules exist to prevent.

### `taxonomy() → topic vocabulary`

**The label vocabulary**, so a caller's own labels resolve to context. An **empty result is
legal** and means the project keeps no controlled vocabulary — not that the call failed.

## Capability declaration

Every adapter states, near the top, what it supports. This is what makes degradation visible
rather than silent, and it is the first thing a doctor reads:

```markdown
## Capabilities
supports:    locate(topics), locate(paths), taxonomy()
costly:      locate(paths)        # answers, but scans the tree per call
unsupported: record()             # this source is read-only
```

**Three tiers, and `costly` is not a nicety:** a source can answer and still be expensive at
scale, which is neither *supported* (a caller would fan out over everything) nor *unsupported*
(the data is genuinely there). A caller seeing `costly` narrows first, or delegates the sweep.

### The floor

| Operation | May be |
|---|---|
| `locate` | **required.** A source that cannot say what applies here is not a doc system — bind `none` instead and be honest |
| `record` | `unsupported` — a read-only source (a wiki no tool may write) is a legitimate binding |
| `taxonomy` | `supports` with an empty result — an absent vocabulary is not a failure |

## Two prohibitions

- **Never work around a missing capability** by writing data somewhere the source does not model.
- **Never invent the data.** An optional field a source cannot store is not an error; fabricating
  it is.
