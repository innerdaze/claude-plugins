# v2 — repoint knowledge content at paths that moved

**What changed:** Nothing in the knowledge system's *shape*. What changes is that its files stop
pointing at locations the delivery scaffolding moved out from under them.

When the config bus moved to `.agent/PROJECT.md`, and the ticket-flow overlay and its extracted
rules moved to `.agent/work/`, the migration that moved them repointed the references inside its
*own* files and correctly stopped there: `domains/**` is this role's content, and no other role
may edit it. So a migrated project is left with knowledge files naming paths that no longer
exist, and this is the only migration allowed to fix them.

**This is a repoint, not a refresh.** It substitutes paths and changes nothing else — every line
that is not one of those references is byte-identical afterwards. Judging whether a topic file
still *describes the codebase* is `prep refresh`, which re-scans the repo: that produces a
different diff for every person who runs it, so it cannot live inside a migration and is reported
as a follow-up instead.

**Preconditions:** the bus is at `.agent/PROJECT.md`. If it is still at the legacy
`domains/PROJECT.md`, decline with "waiting on the bus move" — repointing references to a file
that has not moved yet would point them at nothing.

**Apply (v1 → v2):**

1. **Read the new locations from `## Artifacts`, never from another plugin's files.** The bus's
   own path is frozen-core. The overlay's is the `Ticket flow` row; its extracted rules are the
   `Ticket flow rules` row. **The registry is the authority**: if a row names a path different
   from the one below, the row wins — that is the whole reason the table exists.

2. **Substitute these references throughout `domains/**`.** The left column is where the
   delivery scaffolding used to keep each file — a fact about this repo's past, which is why it
   can be stated here rather than discovered:

   | Old reference | New location |
   |---|---|
   | `domains/PROJECT.md` | the bus: `.agent/PROJECT.md` |
   | `domains/workflow.md` | the `Ticket flow` row's path |
   | `.claude/rules/workflow/` | the `Ticket flow rules` row's path |

   **If a row is absent, repoint nothing for it and list those references in your report.** An
   absent row means its owner has not registered that artifact, and inferring where it went from
   the shape of the old path is exactly the guess the registry removes. Report and move on.

3. **Fix `meta.md`'s description of the layout.** It is this plugin's generated guide and it lists
   the files that live in `domains/`, which still includes the bus. Remove `PROJECT.md` from that
   list — it is not in this folder any more and naming it there sends a reader to a file that
   moved — and point any remaining mention of it at the bus's path. Leave every project-specific
   rule in that file untouched.

4. **Touch no topic content beyond the substitution.** Do not re-scan the repo, do not rewrite a
   topic, do not add or remove a manifest row, do not "improve" a sentence you are already
   editing the path in. One kind of change, so the diff can be read rather than skimmed.

5. **Report**, and make the follow-up findable rather than memorable:
   - every file and line you repointed;
   - every reference you left alone, with the row that was missing;
   - that topic *accuracy* is unverified by this migration, and `prep refresh` is what checks it.

   Do not tell the user to "remember to refresh". `/domains:doctor` reports dangling references
   and stale-looking topics until they are dealt with, which is what a reminder cannot do.
