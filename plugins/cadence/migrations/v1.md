# v1 — split the config, move the root

**What changed:** Cadence's bindings moved into the shared config bus, its methodology stayed
under its own root, and that root moved from `.claude/cadence/` to `.agent/cadence/`.

**Preconditions:** none for the root move. The **bus must exist** for the split half — if
`.agent/PROJECT.md` is absent, do the root move, then **decline the split** and say "waiting on
the config bus"; an orchestrating `migrate` retries after whichever tool creates it. Do **not**
create the bus here just to proceed: creating it is legitimate for any tool, but a migration
that half-declines is easier to reason about than one that invents a file to finish itself.

**Apply (v0 → v1):**

1. **Move the root.** `git mv .claude/cadence .agent/cadence` (create `.agent/` if needed). Use
   the VCS's move so history follows. If `.agent/cadence/` already exists, **stop and report** —
   two roots is not a state to resolve by guessing.

2. **Re-point the ignore entry.** The session-state file is ignored by path; the old entry now
   matches nothing. Replace `.claude/cadence/SESSION.local.md` with
   `.agent/cadence/SESSION.local.md` in the project's ignore file, through the VCS adapter's
   `ignore()`. ⚠️ **Do this in the same change as the move.** A moved session file with a stale
   ignore entry gets committed by the next person who runs `add -A`, and it is exactly the
   high-churn single-author file that must never be shared.

3. **Split the config.** From `.agent/cadence/config.md`, move these into the bus and **delete
   them from cadence's own config** — the deletion is the point, since two copies drift:

   | Key | Goes to |
   |---|---|
   | `tracker` | `## Tracker` (a **`shared`** section) — **only if absent.** Present ⇒ read it, drop your copy, change neither the values nor the marker. There is no takeover |
   | `execution` | `## Execution` — this one *is* yours |
   | `vcs` | `## Version control` (`shared`) — absent ⇒ write, present ⇒ read and drop |
   | `doc_system` | the `Doc system` binding row — absent ⇒ write, present ⇒ read and drop |

   Verification, if cadence's config holds a copy, follows the same rule against
   `## Verification` (`shared`).

   Keep `flow`, `dod_gates`, `session_state`, `models` and `cadence_version` where they are.
   Only cadence can use them, and the test is whether a second tool could.

4. **Register.** Add `| cadence methodology | 1 | methodology |` to `## Versions`, and
   `| methodology | /cadence:migrate | /cadence:init |` to `## Commands`. Write no other role's
   rows.

5. **Verify before stamping.** Re-read both files: the bus parses, the sections you wrote are
   present with your owner marker, cadence's config still resolves its flow, and the ignore entry
   points at the file that now exists. Only then stamp.

6. **Report what moved**, and name the one thing a user might otherwise trip over: any local
   scripts, aliases or docs of theirs that referenced `.claude/cadence/` now point at nothing.
   The migration cannot find those, so say it rather than leaving it to be discovered.
