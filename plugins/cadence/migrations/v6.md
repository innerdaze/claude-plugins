# v6 — sharing `.agent/local`

**What changed:** `.agent/local` is now **created and shared by cadence**, not left to the user.
Three defects made the sharing v2 described impossible in practice:

- every ignore entry read `.agent/local/` — slash form, which matches a directory but **not a
  symlink to one**, so the moment someone linked the folder the link showed up as untracked;
- the VCS adapter's `shared_local_dir()` returned `<common .git>/cadence/` while every doc said to
  link `.agent/local` to `<common .git>/agent-local`, so session start's "is it shared?" check
  never passed and cross-worktree claims never switched on;
- `/cadence:init` defaulted `session_state.file` to the unkeyed `.agent/local/cadence-session.md`,
  which two worktrees collide on as soon as the folder is shared.

The ignore entry is now `.agent/local` (no slash), `shared_local_dir()` names the absolute
`<common .git>/agent-local/`, and init and every session start link `.agent/local` to it.

**Preconditions:** none.

**Apply (v5 → v6):**

1. **Share `.agent/local`.** Apply `${CLAUDE_PLUGIN_ROOT}/checks/LOCAL-DIR.md` to this worktree — it
   rewrites a slash-form ignore line in place and links the folder, asking only when a plain
   folder already holds files. If the person declines that move, it stops on a name collision, or
   it reports the folder broken, leave the folder exactly as it left it, carry on with the steps
   below, and say so in the report, naming both paths of any collision. This does not hold the
   stamp back: that procedure runs again at every `/cadence:session start`, so sharing is finished there once a person has
   resolved what stopped it, without a migration.

2. **Key the session file by worktree.** Read `session_state.file` in `.agent/cadence/config.md`.
   - **Exactly `.agent/local/cadence-session.md`** — the old unkeyed default:
     1. If `.agent/local/cadence-session.md` exists **and** a file with this worktree's keyed
        name (`<worktree>` = the basename of the working tree's root) is already beside it,
        **stop and report both** — one of them is another session's, and picking is not yours to
        do. Change nothing in this step, so a re-run after the person has chosen still finds the
        old default and finishes it.
     2. Otherwise move this worktree's file, if there is one, to
        `.agent/local/cadence-session-<worktree>.md`. A plain filesystem move, as in v2: the file
        is ignored, so the VCS does not know it.
     3. Rewrite `session_state.file` to `.agent/local/cadence-session-<worktree>.md`, with
        `<worktree>` as a **literal** part of the pattern so every checkout resolves to its own
        file.
   - **Already keyed, or any other path** → leave it. A custom path is a choice someone made.

   Only this worktree's file moves. The config is committed, so other worktrees pick up the keyed
   name with it; one that still has an unkeyed `cadence-session.md` of its own — in a folder that
   was not shared — keeps it until someone renames it, and its next session starts from an empty
   scratchpad. Say that in the report when the folder was not shared before step 1.

3. **Report on the old shared folder.** For git, look at
   `$(git rev-parse --path-format=absolute --git-common-dir)/cadence/` — what `shared_local_dir()`
   used to return and create.
   - **`.agent/local` links there** → it is **in use**, and that is fine: a link to any existing
     folder outside the working tree counts as shared, so there is nothing to migrate. Say so.
   - **It exists and nothing links to it** → **unused, and safe to delete** — say that in one
     line, with the path. **Never delete it yourself**: it is outside the repo, and another
     worktree's link is not something this one can see.
   - **Absent** → say nothing.

   A VCS other than git has no such folder; skip this step.

4. **Report**: what `LOCAL-DIR.md` did (linked, already shared, converted, declined, broken), the
   `session_state.file` rewrite and the file move if either happened, and the old folder's status
   from step 3. Then stamp `cadence methodology` at 6 — unless step 2 stopped on a collision, in
   which case do not stamp: a second run after the person has chosen finishes the move.

   **Which stop holds the stamp back, plainly:**

   | Stopped in | Stamp |
   |---|---|
   | Step 1 — `LOCAL-DIR.md` declined, stopped on a name collision, or reported the folder broken | **6.** Step 1 is per-worktree setup that `/cadence:session start` re-applies, so it is finished there; for the migrate skill's "only after everything in range succeeded", a step 1 that reported its stop has succeeded |
   | Step 2 — both the unkeyed and the keyed session file exist | **Stays at 5.** The rewrite in the committed config has not happened, and only a second run of this migration does it |

   Both can happen in one run; then step 2 decides, and the stamp stays at 5.

`[note]` The slash-form entry was written by cadence's own `ignore()`, v2 of these migrations, and
init — so every project that followed the docs and linked the folder got an untracked link.
Nothing could have relied on the old `shared_local_dir()` value, because the comparison it fed
never succeeded.
