# v4 — the doc-system adapter is named by the bus's kind

**What changed:** cadence's project-local doc-system adapter lives at
`.agent/cadence/adapters/docs/<kind>.md`, where `<kind>` is **the value of the bus's `Doc system`
binding row** — nothing else. Older `/cadence:init` runs invented a name for a knowledge system
they recognised (`domains`) and generated `docs/domains.md`, while the knowledge tool's own init
writes the row as `markdown`. A project with both then resolves to nothing on cadence's side, and
the knowledge tool's doctor reports a kind nobody implements. Cadence now also ships
`adapters/docs/markdown.md`, so a `markdown` row resolves without any generated file.

**Preconditions:** the bus is at `.agent/PROJECT.md` and carries a `Doc system` row in
`## Bindings`. Absent → decline with "waiting on a Doc system binding" — `/cadence:init` or the
knowledge tool's init writes it, and renaming a file to a kind nobody has stated is a guess.

**The row's value must be a kind something implements** — `none`, `markdown`, or a kind for which
a project-local adapter will exist after this migration. If it names a kind no shipped fallback
implements and no adapter file can be renamed to it, **decline** and say exactly what to do: the
row is `shared`, so this migration does not rewrite it; the user edits it by hand to `markdown`
(when a knowledge folder is registered) or `none`, and re-runs `/cadence:migrate`. The known case
is a row reading `domains`, written by cadence's own v1 migration from a config that used the
invented name.

**Apply (v3 → v4):**

1. **Read `<kind>`** from the bus's `Doc system` row.

2. **If `.agent/cadence/adapters/docs/<kind>.md` exists**, or `<kind>` is `none` or `markdown`
   with no project-local `docs/` adapter at all → nothing to rename. Go to step 5.

3. **If exactly one file exists under `.agent/cadence/adapters/docs/`** and it is not
   `<kind>.md` → **move it to `<kind>.md` with the VCS's move**, so history follows. Inside it,
   replace a `kind: <old name>` line, if present, with `kind: <kind>`; change nothing else. Report
   the old and new names.

4. **If more than one file exists there** → stop and report them. Which one is this project's
   real adapter is not deterministic, and a person picks. Do not stamp.

5. **Report**: the rename if any, and — where `<kind>` is `markdown` and a generated adapter now
   sits at `markdown.md` — that the project-local file outranks the shipped fallback and is kept
   as is. Touch nothing else: not the row, not the adapter's operations, not the config.

`[note]` This is the same class of defect as v3's duplicated `project:` block: two tools each
holding a copy of one fact and one of them inventing the vocabulary. The fix is the same shape —
the bus's value wins, and cadence's file follows it.
