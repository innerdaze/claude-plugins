# v2 — session state moves to `.agent/local/`

**What changed:** Cadence's session scratchpad moves from `.agent/cadence/SESSION.local.md` to
**`.agent/local/cadence-session-<worktree>.md`**, and its ignore entry moves with it.

The scratchpad is the only file cadence writes that must never be committed. Keeping it beside
the committed config meant an ignore entry per file, and v1 of this migration already had to
repair one that had stopped matching after the root moved — an entry matching nothing looks
exactly like one that works, and the first symptom is a session file in somebody's diff.

`.agent/local/` is ignored as a directory, so there is one entry for everything uncommitted. It is
*meant to be shared* between worktrees — it holds this developer's preferences — so the session
file carries the worktree in its **name** rather than relying on the directory to separate
checkouts. That is what stops two worktrees overwriting each other's goal, and it holds whether
or not the user has linked the directory.

**Preconditions:** cadence's root is at `.agent/cadence/` (v1). Decline with "waiting on v1"
otherwise.

**Apply (v1 → v2):**

1. **Ignore the directory.** Ensure the project's ignore file ignores `.agent/local/`, through the
   VCS adapter's `ignore(paths)` operation — idempotent, and it creates the ignore file if there
   is none.

2. **Use `.agent/local/` if it is there; create it only if it is not.** If it already exists —
   as a directory *or a symlink* — use it as found and change nothing about it. The link is how a
   user shares one local directory across worktrees, and replacing it would undo that.

   If it is absent, create a plain directory and **say one line**: anyone using worktrees should
   replace it with a symlink to a shared target, and doing that later means merging directories
   by hand. Never follow a link to somewhere outside the repo and start reorganising what you
   find; you are placing one file.

3. **Move the file if it exists.** `.agent/cadence/SESSION.local.md` →
   `.agent/local/cadence-session-<worktree>.md`, where `<worktree>` is the basename of the
   working tree's root. Do **not** use the VCS's move: the file is ignored, so it is not tracked,
   and asking a VCS to move an untracked file is asking it about something it does not know. A
   plain filesystem move is correct here, and it is the one place in these migrations where that
   is true.

   If a file with that name is already there, **stop and report both** — one of them is another
   session's, and picking is not yours to do.

   If the file does not exist, nothing to move. A project that has never run a session has no
   scratchpad, which is the normal state for a fresh install.

4. **Remove the now-dead ignore entry.** Delete any entry naming
   `.agent/cadence/SESSION.local.md` (or the older `.claude/cadence/SESSION.local.md`). Leave
   every other line in that file alone — it is the project's, and cadence has exactly two lines'
   worth of business in it.

   ⚠️ **Removing the entry before the file has moved would expose the file.** Order matters: move
   first, then unignore the old path. If step 3 declined — the file was unreadable, or a file
   already existed at the destination — **do not** do this step.

5. **Update the config.** `session_state.file` in `.agent/cadence/config.md` becomes
   `.agent/local/cadence-session-<worktree>.md` — with the worktree key as a literal part of the
   pattern, so a second checkout resolves to its own file rather than this one's. If the project had pointed it somewhere else deliberately —
   a path that is neither the old default nor the new one — **leave it, and say so**: that is a
   choice someone made, and this migration is not evidence they were wrong.

6. **Say what a session will do differently.** One line: session state is now per working copy,
   so two worktrees no longer share a goal. For anyone who has been running two checkouts, that
   is a behaviour change and a bug fix at the same time, and they should hear it from the
   migration rather than notice it later.

7. **Report** the move, the ignore lines added and removed, and whether the config pointed
   somewhere custom.
