# v2 — register rows keyed by content, never by ordinal

**What changed:** the register template keys rows by a slug derived from the row's subject
(`bus/neutral-path`, `gates/applicability`) instead of a sequential number. A number is a
function of position and count, so only a writer holding the current state can assign it — and
two capture passes in one working tree both computed `max+1` from a stale read and collided,
silently, five times. A slug cannot collide by accident. The rule is stated in the plugin's own
intent layer as `honesty/content-keys`.

**This migration does the deterministic half only.** Choosing a *subject* slug is a judgement
about what a row is about, and two people would choose differently — so it cannot live here.
What can: give every ordinal-keyed row a key that is unique, stable and cannot be minted twice,
and record the mapping. `/intent:capture` offers the subject slugs afterwards, with the
maintainer present.

**Preconditions:** the bus is at `.agent/PROJECT.md` and carries an `## Artifacts` row owned by
`intent-layer`. Absent → decline with "waiting on registration"; the folder cannot be located
without guessing, and guessing is the thing the registry removes.

**Apply (v1 → v2):**

1. **Read the folder from the artifact row.** The register is `<that path>/alignment.md`. If the
   file does not exist there is nothing to re-key: apply nothing and continue to the stamp — a
   layer with no register is `/intent:doctor`'s finding, not this migration's.

2. **Rename the key column.** In every table whose header's first cell is `#`, change that cell
   to `Row`. Nothing else in the header line moves.

3. **Re-key every ordinal row, verbatim and in place.** A row's key is its first cell. It is
   ordinal when it is a bare integer (`12`), an integer with one lowercase suffix (`2a`), one or
   two capital letters followed by an integer (`D7`, `S10`, `C1`), or a single capital letter
   (`C`). Replace the cell with `` `legacy/<key>` ``, case preserved — `| 12 |` becomes
   `` | `legacy/12` | ``, `| D7 |` becomes `` | `legacy/D7` | ``. A first cell already wrapped in
   backticks is a slug and is left alone, so a hand-converted register is untouched and a
   half-converted one is finished.

4. **Append the mapping, permanently.** At the end of the file, a section:

   ```markdown
   ## Legacy numbering

   Rows were keyed by ordinal until this layer was migrated to v2, when every register moved
   to content slugs. Commit messages and tickets from before then quote the old numbers; this
   table is permanent so they still resolve. Keys of the form `legacy/<n>` are placeholders
   awaiting a subject slug from `/intent:capture`.

   | Was | Now |
   |---|---|
   | 12 | `legacy/12` |
   ```

   One row per key you changed, in file order. If the section already exists, add only the rows
   not already in it and leave its prose alone.

5. **Touch nothing else.** No row content, no marker, no citation anywhere in the layer's other
   documents — a `#12` in a topic doc still resolves through the table, which is why the table is
   permanent. Not a word of prose. One kind of change, so the diff can be read rather than
   skimmed.

6. **Report**: how many rows were re-keyed (zero is a normal answer — this repo's registers may
   already be slugged by hand), and the follow-up made findable rather than memorable:
   `/intent:capture` offers subject slugs for every `legacy/` key, and `/intent:doctor` lists the
   `legacy/` keys still outstanding until it does.
